Put the lock in the code: why an AI's "no" is not access control

Arize's test support agent refused every direct request to send data out, yet pulled a stranger's record in 28 of 100 runs until its tools were scoped to the signed-in customer. Here are the sources, plus the confused deputy, the 1988 idea behind it.

Sources

  1. ArticleArize: A web page talked our agent into leaking a stranger's data

    Nancy Chauhan (Oct 2026): 98 of 98 direct requests refused, 28 of 100 routine-sounding lookups leaked, 0 leaks once every customer tool was bound to the logged-in session in code. arize.com

  2. ArticleNoma Labs: Workflow Identity Hijacking

    Sasi Levi: an ordinary email to a public support inbox got quarterly sales numbers back, because the AI workflow ran with its creator's privileges. No prompt injection needed. noma.security

  3. ArticleZenity Labs: AgentCorruption

    One prompt to an exposed AWS Bedrock AgentCore agent reached the metadata service and returned credentials for a default role that spanned every AgentCore agent in the account's region. AWS hardened the role by Sept 29, 2026. labs.zenity.io

  4. PaperWhen Approval Becomes Execution (Shi, Mou)

    A denied agent fetched a routine approval token and completed the protected operation in 8 of 9 reruns: possession of a token was treated as permission. arxiv.org

  5. StandardMCP Security Best Practices: Confused Deputy Problem

    The official MCP guidance on confused deputies and token passthrough: servers must not accept tokens that were not issued for them. modelcontextprotocol.io

  6. StandardOWASP: Securing Agentic Applications V2

    A builder and defender's guide released Nov 10, 2026, covering architecture, identity and access controls, runtime protection, supply chain, and testing. genai.owasp.org

  7. ArticlePortSwigger lab: Exploiting LLM APIs with excessive agency

    Free, in the browser: get a website's AI chat to delete a user through an API it should never have let you reach. portswigger.net
